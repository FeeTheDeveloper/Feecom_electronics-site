# Feecom Electronics & Exchange LLC

Marketing website for Feecom Electronics & Exchange LLC, built with Next.js App Router and prepared for an initial Vercel deployment.

## Stack

- Next.js 15
- React 18
- TypeScript
- Tailwind CSS
- ESLint
- Prettier
- Husky + lint-staged
- Node.js 20.x

## Project Status

- Production build passes locally with `npm run build`
- Lint passes with `npm run lint`
- Formatting passes with `npm run format:check`
- No runtime environment variables are required for the initial deployment
- Vercel-friendly metadata, `robots.txt`, sitemap, and manifest are generated by the app

## Deployment Readiness

This repo is set up so Vercel can deploy it without custom build configuration.

- Framework preset: `Next.js`
- Install command: `npm install`
- Build command: `npm run build`
- Output directory: leave blank and let Vercel manage `.next`
- Root directory: repository root
- Production branch: `main`

### Important Node.js note

Vercel's default Node.js version for new projects is currently `24.x`, while this repo is pinned to `20.x` in `package.json` and `.nvmrc`.

Keep the project on Node `20.x` for the initial deployment so local and remote builds stay aligned.

## First Vercel Deployment

### Git-based deployment

1. Push the branch you want to deploy to GitHub.
2. In Vercel, click `Add New` -> `Project`.
3. Import `FeeTheDeveloper/Feecom_electronics-site`.
4. Confirm these settings:
   - Framework Preset: `Next.js`
   - Root Directory: repo root
   - Install Command: `npm install`
   - Build Command: `npm run build`
5. In Project Settings, confirm Node.js Version is `20.x`.
6. Deploy.

### What to expect

- The first import creates a preview or production deployment depending on the branch you deploy.
- Pushes to `main` create production deployments.
- Pushes to other branches create preview deployments.

## Custom Domain Setup

Use `feecomelectronics.com` as the production domain and `www.feecomelectronics.com` as the redirect or secondary domain.

### Apex domain

Point the apex domain to Vercel with an `A` record:

- Host: `@`
- Value: `76.76.21.21`

### WWW subdomain

Point `www` to Vercel with a `CNAME` record:

- Host: `www`
- Value: `cname.vercel-dns.com`

Then add both domains in Vercel under `Project Settings -> Domains`.

## Environment Variables

No environment variables are required for the current app.

Optional:

- `NEXT_PUBLIC_SITE_URL`
  Use this only if you want to force a specific canonical site URL outside the default production domain behavior.

If you later add secrets or API credentials, configure them in Vercel under `Project Settings -> Environment Variables`.

1. Merge the release branch into `main`.
2. Verify the deployed preview matches the intended design.
3. Add the production domain in Vercel.
4. Confirm SSL is issued and the domain resolves correctly.
5. Re-run `npm run lint` and `npm run build` before the production merge if content changes were made.

## Troubleshooting

### Build fails on a different Node version

Use Node `20.x` locally and in Vercel project settings.

### Deployment builds the wrong directory

Set the Vercel Root Directory to the repository root, not a parent folder.

### Environment variables do not appear in a deployment

Add them in Vercel project settings and redeploy. New environment variable values only apply to new deployments.
